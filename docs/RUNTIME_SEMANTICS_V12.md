# Runtime semantics v0.12

This change set makes Juriscribe's strongest runtime claims derived, scoped and cheaper to initialize without adding a parallel framework.

## Definition of done

1. C&C candidate sealing cannot accept caller-supplied recall scores as proof.
2. Structural preservation is recomputed from current state, refined text and a text-bound semantic projection, then revalidated at completion.
3. Stress receipts distinguish executed instance volume from distinct equivalence classes and reject inconsistent class counts/digests.
4. The canonical serialized/user-visible mode is `COMPRESSION & CONSOLIDATION`; the historical underscore spelling is compatibility-only.
5. Bootstrap source transport can use a declared minimal import closure and defer full runtime expansion without weakening revision/contract/receipt binding.
6. Current runtime surface is explicit; historical docs are compatibility/audit material.
7. The checkout is PEP 517 packageable and an installed runtime carries a byte-equivalent access contract resource.

## Proof-carrying semantics

`juriscribe.semantic_proof` derives `JURISCRIBE_PROOF_CARRYING_SEMANTICS_V1` from the current candidate source, inventory, refactoring plan, reticulum, canonical inventory set, refined text and semantic projection. It rejects lost/new material units, lost/new or mutated material relations, unknown output-object bindings, false text witnesses, stale bindings and proof tampering.

The claim is intentionally narrow: structural semantic preservation is not independent legal truth, substantive equivalence or entailment. Scientific/editorial review, source verification and human professional judgment remain separate gates.

## Stress evidence

The existing minimum 10,000,000 mutation-instance campaign remains useful as soak volume. It is no longer described as 10,000,000 unique semantic cases. Current evidence binds instance counts to named equivalence classes, class counts, mismatch status and a digest. A focused 100k proof-mutation campaign covers lost unit, new unit, lost relation, changed relation, unknown object, false witness, source spoof, role spoof and proof tamper.

Saturation is a pre-materialization search-convergence claim. Caller-provided `semantic_recall` / `relation_recall` is rejected there; refined-candidate preservation is derived only after the actual refined text exists.

## Bootstrap optimization

The reported roughly five-minute post-initialize bootstrap had no raw timing log attached to this change request, so the fix targets the avoidable cost visible in the protocol itself. `ADMISSION.json` now declares an exact `bootstrap_source_paths` import closure. With `SESSION_CONTEXT=AVAILABLE`, a host can transport only this closure, validate retained acceptance, issue real admission/probe receipts, initialize a memory session and render mode selection in one host turn. Full runtime transport is deferred until substantive work.

This reduces repository discovery/materialization round trips while preserving revision binding, contract hash binding, single-use probe receipts and sealed capabilities. If a real trace remains slow after this change, the next investigation should measure source-bridge/network latency and persistence/dashboard I/O rather than relax bootstrap invariants.

## Compatibility note

The Python symbol `COMPRESSION_CONSOLIDATION` remains as an internal compatibility alias because `&` is not a valid Python identifier. Historical audit documents may also retain old text as immutable history. Canonical runtime values, contracts, schemas, manifests and current user-facing documentation use `COMPRESSION & CONSOLIDATION`.
