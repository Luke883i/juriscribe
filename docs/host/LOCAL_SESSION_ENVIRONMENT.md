# Juriscribe Local Session Environment v1.2

Authority: `HOST_COMPOSITION_ONLY` — no scientific, legal, mode, proof, materialization, delivery or completion authority.

This is the normative root contract for a conversational host. It is binding only after valid human acceptance and only when loaded from the same revision pinned to that acceptance context.

## Identity

The persisted scientific session remains the durable, transport-independent asset. A compliant conversational host composes canonical binding, executable runtime when selected/available, state carrier, interaction, artifacts, delivery and recovery as one revision-bound local environment. The host never becomes a second Juriscribe implementation.

`METHOD_ACCESS` is defined by the accepted access contract and `METHOD_KERNEL.json`; runtime authority remains owned by the canonical runtime. `LOCAL_CHAT` is only a host bootstrap/UX specialization.

## Normative graph

The lifecycle-scoped normative nodes remain:

- [`EXECUTION.md`](EXECUTION.md) — binding, `LOCAL_CHAT` transport, explicit execution-profile handoff and runtime bootstrap.
- [`STATE.md`](STATE.md) — canonical state, host context continuity and replay boundaries.
- [`SURFACE.md`](SURFACE.md) — chat, choices, artifacts and infrastructure disclosure.
- [`FAILURE_RECOVERY.md`](FAILURE_RECOVERY.md) — failure classification, remediation, recovery and admissible blockers.

[`LOCAL_HOST_PROMPT.md`](LOCAL_HOST_PROMPT.md) is the standalone revision-bound boot/cognitive policy. It replaces the need to load a separate runtime-local-host companion and adds no scientific/runtime authority. `RUNTIME_LOCAL_HOST.md` is retained only as a historical compatibility pointer.

## Activation

Use only the normative nodes named by `ADMISSION.json.local_session_environment.activation` for the current trigger:

- `POST_ACCEPTANCE_BOOTSTRAP` → ROOT + EXECUTION.
- `ACTIVE_SESSION` → ROOT + STATE + SURFACE.
- `FAILURE_OR_RECOVERY` → ROOT + STATE + FAILURE_RECOVERY.
- `REBIND_OR_TRANSPORT_FAILURE` → ROOT + EXECUTION + FAILURE_RECOVERY.

All active files and the standalone prompt policy must come from the same pinned revision. Never silently rebind an active session to a newer `main`.

## Precedence

Host system/safety/law and the accepted Juriscribe access contract retain precedence. Runtime phase, mode, proof, receipt, checkpoint, artifact, delivery and completion facts remain canonical runtime facts. `METHOD_MODE_INTENT` in LEAN is not `MODE_SELECTED`.

If a host document conflicts with the access contract, `ADMISSION.json`, `METHOD_KERNEL.json`, runtime state or a canonical runtime receipt, the canonical source wins and the conflict is surfaced through failure/recovery. Do not shadow-patch authority in the prompt.

## Invariants

1. `UNVERIFIED != UNAVAILABLE != AVAILABLE`, except explicit non-probed `LOCAL_CHAT` priors declared by contract.
2. Repository readability is not runtime execution.
3. Byte-verified canonical source transport is not reimplementation.
4. Acceptance evidence is not a runtime receipt.
5. `LEAN` never degrades method, epistemic discipline, artifact obligations or human validation.
6. `ATTESTED` claims require real runtime evidence; runtime reachability alone never implies `COMPLETE`.
7. LEAN → ATTESTED requires canonical replay/revalidation.
8. `LOCAL_CHAT` does not roam into Git/DNS/install alternatives after the connected-GitHub primary path fails.
9. Physical artifact readiness and execution attestation are separate axes.
10. The five host normative concerns and six runtime authority nodes remain unchanged.
