# Juriscribe Local Session Environment v1.1

Authority: `HOST_COMPOSITION_ONLY` — no scientific, legal, mode, proof, materialization, delivery or completion authority.

This is the normative root contract for a conversational host. It is binding only after valid human acceptance and only when loaded from the same revision pinned to that acceptance context.

## Identity

The persisted scientific session remains the durable, transport-independent asset. A compliant conversational host composes canonical binding, executable runtime when available, state carrier, interaction, artifacts, delivery and recovery as one revision-bound local environment. The host never becomes a second Juriscribe implementation.

Graded execution does not change this authority boundary. `METHOD_ACCESS` is defined by the accepted access contract and `METHOD_KERNEL.json`; runtime authority remains owned by the canonical runtime.

## Normative graph

The lifecycle-scoped normative nodes remain:

- [`EXECUTION.md`](EXECUTION.md) — discovery, binding, runtime transport, local-search exhaustion and execution-profile handoff.
- [`STATE.md`](STATE.md) — canonical state, host context continuity and replay boundaries.
- [`SURFACE.md`](SURFACE.md) — chat, choices, artifacts and infrastructure disclosure.
- [`FAILURE_RECOVERY.md`](FAILURE_RECOVERY.md) — failure classification, remediation, recovery and admissible blockers.

[`RUNTIME_LOCAL_HOST.md`](RUNTIME_LOCAL_HOST.md) is a same-revision **cognitive companion** initialized by [`LOCAL_HOST_PROMPT.md`](LOCAL_HOST_PROMPT.md). It helps the host search, remember observed facts and project graded execution; it is not a normative replacement for the lifecycle graph and adds no authority.

## Activation

Use only the normative nodes named by `ADMISSION.json.local_session_environment.activation` for the current trigger:

- `POST_ACCEPTANCE_BOOTSTRAP` → ROOT + EXECUTION.
- `ACTIVE_SESSION` → ROOT + STATE + SURFACE.
- `FAILURE_OR_RECOVERY` → ROOT + STATE + FAILURE_RECOVERY.
- `REBIND_OR_TRANSPORT_FAILURE` → ROOT + EXECUTION + FAILURE_RECOVERY.

All active files and the cognitive companion must come from the same pinned revision. Never silently rebind an active session to a newer `main`.

## Precedence

Host system/safety/law and the accepted Juriscribe access contract retain precedence. Runtime phase, mode, proof, receipt, checkpoint, artifact, delivery and completion facts remain canonical runtime facts. `METHOD_MODE_INTENT` in LEAN is not `MODE_SELECTED`.

If a host document conflicts with the access contract, `ADMISSION.json`, `METHOD_KERNEL.json`, runtime state or a canonical runtime receipt, the canonical source wins and the conflict is surfaced through failure/recovery. Do not shadow-patch authority in the prompt or cognitive companion.

## Invariants

1. `UNVERIFIED != UNAVAILABLE != AVAILABLE`.
2. Repository readability is not runtime execution.
3. Materialized canonical source is transport, not reimplementation.
4. Acceptance evidence is not a runtime receipt.
5. `LEAN` never degrades method, epistemic discipline or human validation.
6. `ATTESTED` claims require real runtime evidence; runtime reachability alone never implies `COMPLETE`.
7. Explicit LEAN work remains `METHOD_GUIDED` even when runtime capability is present; later ATTESTED use requires replay/revalidation.
8. Runtime search and LEAN method execution are separate decisions: LEAN is not a transport path class.
9. Physical artifact readiness and execution attestation are separate axes.
10. The five host normative concerns remain lifecycle-scoped and the six runtime authority nodes remain unchanged.
